# Sober Streak — 설계 문서

> 초경량 음주/금주 트래커. 서버 없이 폰에서 매일 한 번 탭.
> 원칙: **주말 안에 끝날 것 + 내가 실제로 쓸 것.** 스코프 커지면 자른다.

---

## 1. 목적 / 가설

- **핵심 가설:** 연속 무알콜 일수(streak)를 눈에 크게 보여주면 끊는 동기가 강해진다 — "쌓은 게 아까워서" 안 마시게 된다.
- **사용자 pain:** 지금 금주 8일차를 머릿속으로 세고 있음. 음주 패턴과 논알콜 대체 사용량이 전혀 안 보임.
- **성공 기준:**
  1. 하루 1탭으로 오늘 기록이 끝난다.
  2. 현재 스트릭 / 최고 기록 / 누적 금주일이 한눈에 보인다.
  3. 데이터가 날아가지 않는다(홈 화면 설치 + JSON 백업).

## 2. 스코프

**만든다 (v1):**
- 오늘 기록: `안 마심` / `마심` + `논알콜` 독립 토글
- 3-숫자 히어로: 현재 스트릭 / 최고 기록 / 누적 금주일
- 캘린더 히트맵 (초록/빨강/회색 + 논알콜 점)
- 온보딩(마지막 음주일 시드 + 홈 화면 추가 안내)
- 설정: JSON export / import, 데이터 초기화

**안 만든다 (v1 스코프 방어):**
- 로그인 / 회원가입 ❌
- 서버 / DB ❌ (localStorage만)
- 소셜 / 공유 ❌
- 알림 / 푸시 ❌
- 목표 설정 ❌ (스트릭이 곧 목표)
- 통계 대시보드 ❌ (히트맵이면 충분)
- 뱃지 / 게이미피케이션 ❌

**v2 이후 (검증 후에만):**
- 지윤과 공유 → 이때 서버 필요 (Postgres @ jell-server). v1에선 절대 X.
- 마운자로/건강 로그 통합
- 마일스톤 뱃지(7/30/100일)

## 3. 설계 결정 로그

| # | 결정 | 선택 | 근거 |
|---|------|------|------|
| Q1 | 미기록 날 처리 | **C. 무소식은 금주 간주, 스트릭 안 끊김** | 스트릭 = "마지막 마심 이후 경과일". 매일 강박적으로 안 눌러도 됨. 히트맵은 미기록을 회색으로 정직하게 표시(초록 위장 X). |
| Q2 | 기존 8일차 시작 | **A. 온보딩서 마지막 음주일 1회 입력** | 날짜 하나면 즉시 8일차. 백필 부담 없음. |
| Q3 | 논알콜 처리 | **A. 독립 토글** | 음주와 별개로 논알콜 대체 사용량을 정확히 집계. 히트맵 색은 음주 기준, 논알콜은 점(•). |
| Q4 | 저장/영속성 | **localStorage only** (서버 X) | iOS 홈 화면 PWA는 Safari 7일 ITP 삭제 **면제**(WebKit 공식). 매일 사용 시 사실상 삭제 안 걸림. 서버 불필요. |
| Q5 | 배포/토폴로지 | **Vercel 정적 배포** | 서버 로직 0이라 부활. |
| — | 상실감 완화 | **B. 3-숫자 안전망 + 무경고 톤** | 리셋은 현재 스트릭만 건드림. 최고·누적은 영구. "금주 위반 효과" 방어. |

### Q4 근거 (durability 리서치 요약)

- WebKit 블로그(2020, [10218](https://webkit.org/blog/10218/full-third-party-cookie-blocking-and-more/)): *"홈 화면에 추가된 웹 앱은 Safari의 일부가 아니라 자체 사용일 카운터를 가지며, 데이터가 삭제될 거라 예상하지 않는다."*
- 7일 삭제는 **Safari 탭 브라우징 사이트**에만 적용. 홈 화면 설치 PWA는 면제.
- 타이머는 사용할 때마다 리셋 → 매일 여는 앱은 탭에서 써도 사실상 안 걸림.
- iOS 17+ 설치 PWA는 브라우저급 저장 용량(디스크 ~60%) 부여([WebKit 14403](https://webkit.org/blog/14403/updates-to-storage-policy/)).
- localStorage vs IndexedDB: eviction 관점 차이 없음(origin 단위). `navigator.storage.persist()`는 iOS에서 프롬프트 없이 불투명하게 자동 처리 → 방어책으로 의존 X.
- **잔여 위험:** (a) 기기 저장공간 고갈 시 iOS LRU 정리(드묾), (b) 사용자가 홈 화면 아이콘 삭제 시 데이터 소실(재설치해도 복구 X).
- **완화:** 홈 화면 설치(1차) + JSON export/import(2차, 유일한 복구 수단이라 정식 기능으로 격상).

## 4. 데이터 모델 (localStorage)

```ts
type DrinkType = '맥주' | '소주' | '사케' | '와인' | '기타';
type DrinkContext = '회식' | '약속' | '혼술' | '기타';

type DrinkDay = {
  date: string;          // 'YYYY-MM-DD' (KST 기준)
  drank: boolean;
  nonAlcohol: boolean;
  type?: DrinkType;      // drank일 때만 의미
  amount?: string;       // 자유 텍스트 ("맥주 2잔")
  context?: DrinkContext;
};

type Meta = {
  trackingStartDate: string;  // 온보딩 완료일 (누적 계산 하한)
  schemaVersion: number;      // 마이그레이션 대비
};
```

- 저장 형태: `Record<string /*date*/, DrinkDay>` (날짜 키 upsert) + `Meta` 별도 키.
- 하루 = 한 레코드. `date`가 유일키 → 멱등 upsert.
- **시드:** 온보딩의 마지막 음주일 = `DrinkDay{ date: lastDrinkDate, drank: true }` 한 행으로 기록. 별도 필드 불필요.

## 5. 파생 지표 로직 (전부 클라 계산, 저장 추가 0)

`today` = `Asia/Seoul` 기준 오늘 날짜.

- **현재 스트릭** = `today − (가장 최근 drank:true 날짜)` (일 단위). 마신 당일 = 0, 다음 날 = 1 … 자연히 재상승. drank:true가 하나도 없으면 `today − trackingStartDate`.
- **최고 기록** = 모든 "무음주 연속 구간" 중 최대 길이. `drank:true` 날들(+시드) 사이 간격의 최댓값. 현재 진행 중인 스트릭도 후보에 포함.
- **누적 금주일** = `(trackingStartDate ~ today 총일수) − (drank:true 날 수)`. 미기록=금주 간주(Q1 C와 일관).

### 엣지 케이스 (테스트 필수)
- KST 자정 경계: 새벽 2시 음주 = 그날(KST) 소속.
- 미기록 공백: 스트릭·누적에서 금주로 간주, 최고 기록 계산 시에도 연속 유지.
- 시드만 있고 이후 기록 없음: 스트릭 = today − 시드일.
- 과거 정정(히트맵에서 backfill): 파생 지표 즉시 재계산.

## 6. 저장 & Durability 전략

- **1차 방어:** 온보딩 마지막에 "홈 화면에 추가" 안내 → ITP 7일 삭제 면제.
- **2차 방어:** 설정의 JSON export/import. 전체 `DrinkDay[]` + `Meta`를 파일로. import는 병합(날짜 upsert, 최신 우선).
- localStorage 쓰기는 동기라 별도 큐/재시도 불필요(서버 없음).

## 7. 화면 / UX

### 온보딩 (첫 실행 1회)
1. "마지막으로 마신 날은?" → 날짜 선택 → 시드 → 즉시 N일차.
2. "홈 화면에 추가하기" 안내(플랫폼별 가이드).

### 화면 1 — 메인 (히어로)
```
          현재 스트릭
             8일
           무알콜 💧
     최고 24일 · 누적 112일      ← 작게, 영구(안전망)

     오늘 마셨어?
     [ 안 마심 ]   [ 마심 ]
     ┌───────────────────────┐
     │ 🍺🚫 논알콜 마심     ○ │  ← 독립 토글
     └───────────────────────┘
```
- `마심` 탭 → 옵션 시트(종류/양/상황, **전부 스킵 가능**).
- 이미 기록한 날이면 버튼이 현재 상태 반영 → 재탭으로 변경.

### 화면 2 — 캘린더 히트맵
- 월 단위 잔디밭: 초록(안 마심) / 빨강(마심) / 회색(미기록) + 논알콜 점(•).
- 날짜 탭 → 그날 상세·수정(과거 backfill/정정).

### 화면 3 — 설정
- JSON export / import
- 마지막 음주일 재설정 / 데이터 초기화

### 톤 원칙 ("마신 날" 처리)
- 빨간 경고·실패 문구 **없음**. 히어로에 "0" 대문짝 X.
- 마신 당일은 **최고·누적을 전면**에 두고 "다시 시작" 톤. 다음 날부터 현재 스트릭 재상승.
- 히트맵이 전체 그림을 보여줘 빨강 한두 칸은 성공한 달의 일부로 읽힘.

### 네비게이션
- 하단 탭 3개: 메인 / 캘린더 / 설정. 메인이 기본.

## 8. 기술 스택

- **Next.js 15 (App Router) + React 19 + TypeScript** — 전부 클라이언트, 서버 로직 0.
- **PWA:** Serwist(설치형 + 오프라인 셸).
- **배포:** Vercel.
- **라이브러리 최소화.** 히트맵은 자체 그리드(외부 차트 불필요). 날짜는 표준 API + KST 헬퍼.
- 비주얼 방향은 **frontend-design 스킬**로 별도 확정(스펙 승인 후 단계).

## 9. 테스트 전략 (TDD, RED→GREEN→REFACTOR)

- **파생 지표 유닛 100%:** 현재 스트릭 / 최고 / 누적, 위 엣지 케이스 전부.
- **저장 유닛:** localStorage 읽기·쓰기·upsert, Meta.
- **백업 유닛:** export→import 왕복 무손실, 병합 규칙.
- **E2E(Playwright):** 온보딩 → 탭 기록 → 새로고침 → 스트릭 생존. 마신 날 무경고 톤 확인.
- 커버리지 ≥80%, 신규 코드(특히 지표 로직) 100%.
